## 📖 О проекте

**Butler** — это сервис-дворецкий, который живёт в вашем мессенджере и снимает с вас рутину планирования.

Представьте: муж и жена ведут общий список дел, договариваются о встречах, распределяют задачи на день. Кто-то вспомнил, что завтра нужно забрать посылку, кто-то — что в четверг ужин с родителями. Всё это легко теряется в переписке.

Butler решает это так:

- 🎙 **Слушает голосовые** — вы просто наговариваете «напомни завтра в 7 забрать посылку», и это превращается в структурированную запись.
- 📝 **Фиксирует дела и события** — ведёт общий журнал для всей группы.
- 🔔 **Напоминает вовремя** — отдельный компонент `slave` обходит записи и решает, кого и когда уведомить.
- 👨‍👩‍👧 **Работает для узкого круга** — не для тысяч пользователей, а для семьи, пары или небольшой команды, где все друг друга знают.

> Никаких публичных ботов, никаких «ассистентов для всех». Только ваш круг, только ваши дела.

## 🏗 Архитектура

Проект разделён на два независимых сервиса, которые общаются через общее хранилище.

```
                  ┌──────────────────────────────────────────────┐
                  │                 Telegram                     │
                  │      (голосовые, текст, команды)             │
                  └──────────────────────┬───────────────────────┘
                                         │
                                         ▼
                  ┌──────────────────────────────────────────────┐
                  │                  BUTLER                      │
                  │  ─────────────────────────────────────────   │
                  │  • Принимает сообщения из мессенджера        │
                  │  • Распознаёт речь (Whisper)                 │
                  │  • Осмысляет команды и намерения             │
                  │  • Создаёт записи о делах и событиях         │
                  └──────────────────────┬───────────────────────┘
                                         │
                                         ▼
                  ┌──────────────────────────────────────────────┐
                  │               ХРАНИЛИЩЕ                      │
                  │  (дела, события, участники, напоминания)     │
                  └──────────────────────┬───────────────────────┘
                                         │
                                         ▼
                  ┌──────────────────────────────────────────────┐
                  │                   SLAVE                      │
                  │  ─────────────────────────────────────────   │
                  │  • Обходит записи по расписанию              │
                  │  • Определяет, кого уведомить                │
                  │  • Рассылает напоминания участникам          │
                  └──────────────────────────────────────────────┘
```

**Butler** — «уши и руки»: слушает, понимает, записывает.
**Slave** — «память и голос»: помнит, приходит вовремя, напоминает.

Такое разделение позволяет:

- масштабировать напоминания независимо от приёма сообщений;
- перезапускать и обновлять компоненты по отдельности;
- легко добавлять новые каналы (не только Telegram).

## 🚀 Быстрый старт

### 1. Клонирование

```bash
git clone https://github.com/your-username/butler.git
cd butler
```

### 2. Установка uv

Если ещё не установлен — следуйте [инструкции](https://github.com/astral-sh/uv):

```bash
# Linux/macOS
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

### 3. Синхронизация зависимостей

```bash
uv sync
```

### 4. Конфигурация

Создайте рабочий `config.toml` в корне проекта и добавьте ссылку в CONFIG_FILE_PATH в `Makefile`:

```bash
CONFIG_FILE_PATH=src/butler/config.toml
```

Отредактируйте его, указав:

- токен Telegram-бота;
- URL прокси (если требуется);
- директорию для временных файлов (`tmp_dir`).

### 5. Запуск

Все основные команды собраны в `Makefile`:

```bash
make app_run      # запуск бота
make lint         # проверка и автоисправление кода (ruff)
make typecheck    # проверка типов (basedpyright)
make run_tests    # запуск тестов (pytest)
```

`make app_run` выставляет `CONFIG_FILE_PATH=src/butler/config.toml` и запускает `uv run python -m src.butler.main`.

## ⚙️ Как это работает

### Приём голосового сообщения

1. Пользователь отправляет голосовое в Telegram.
2. `handle_voice` скачивает файл в буфер.
3. `WhisperTranscriptor.transcribe` уходит в отдельный поток через `asyncio.to_thread` — event loop не блокируется.
4. Whisper распознаёт речь и возвращает текст.
5. Текст передаётся дальше — на осмысление и создание записи.

### Почему `to_thread`, а не просто вызов

Whisper — синхронная и тяжёлая операция. Если вызвать её напрямую из корутины, бот «замрёт» на всё время распознавания: не сможет принимать другие сообщения, отвечать на команды, обрабатывать апдейты. `asyncio.to_thread` решает это, уводя работу в пул потоков.

## 🤝 Для кого это

Butler не претендует на роль массового продукта. Он создан для **узкого круга близких людей**, где:

- все знают друг друга лично;
- нет нужды в сложной авторизации и ролях;
- важно, чтобы дела и планы были общими и не терялись;
- напоминания должны приходить тем, кого они касаются.

Это может быть пара, семья, небольшая команда друзей или соседей по дому.
